## 1. 개요

### 1.1 문제 정의

화음을 "안다"와 "부를 수 있다"는 전혀 다른 문제다. 화성 감각을 기르고 싶어서 이어 트레이닝 앱을 받아봐도, 대부분 화음을 듣고 객관식으로 맞히는 퀴즈일 뿐 실제로 그 화음을 내 목소리로 낼 수 있는지는 확인해주지 않는다. 반대로 마이크로 노래를 듣고 피드백을 주는 앱들은 대부분 멜로디 한 줄만 추적할 뿐, 그 멜로디에 어울리는 화음이 뭔지는 알려주지 않는다. 결국 "내가 흥얼거린 멜로디에 어떤 화음이 어울리는지 알고 싶고, 그걸 직접 불러서 맞는지 확인받고 싶다"는 니즈는 어느 쪽 앱으로도 채워지지 않는다.

**기존 대안과 한계**

| 대안 | 방식 | 한계 |
|---|---|---|
| 이어 트레이닝 앱 (Chordelia, MelodEar 등) | 화음을 듣고 객관식으로 맞히기 | 실제 발성 정확도를 채점하지 않음 |
| 마이크 기반 피치 모니터 (Nail the Pitch, Pitch Diagram 등) | 단선율 실시간 피치 시각화 | 화음을 자동으로 도출해주지 않음, 다성 분석 불가 |
| 화음 부르기 연습 앱 (Sing Harmonies, Harmony Helper) | 정해진 곡의 화음 파트를 따라 부르며 채점 | 고정 카탈로그/제한된 곡 목록, 내 멜로디를 분석하지 못함 |
| AI 화음 생성 도구 (Musicful, Suno Studio 등) | 멜로디를 주면 화음 오디오를 생성 | 훈련 루프가 아니라 프로덕션 툴, 부르는 연습과 무관 |

### 1.2 제품 목표 및 비전

**비즈니스 목표**: 화성 감각 훈련이라는 니치 영역에서, "멜로디 입력 → 화음 자동 도출 → 발성 훈련"을 하나로 잇는 최초의 앱으로 자리잡는다.

**사용자 가치**: 음악 이론을 몰라도 내가 부른 멜로디에 어울리는 화음을 즉시 알 수 있고, 그 화음을 실제로 부를 수 있을 때까지 정량적인 피드백을 받으며 연습할 수 있다.

### 3.2 핵심 기능 명세

#### 3.2.1 멜로디 입력 및 실시간 피치 트래킹

**사용자 스토리**: As a 화성 감각을 기르고 싶은 사용자, I want to 마이크에 대고 멜로디를 노래하면 실시간으로 내 음정이 표시되는 것을 보고 싶다, so that 내가 정확한 음을 내고 있는지 즉시 확인할 수 있다.

**수용 조건**:
- Given 마이크 권한이 허용된 상태에서, When 사용자가 노래를 부르면, Then 화면에 실시간 피치 곡선이 200ms 이내 지연으로 표시된다.
- Given 배경 소음이 있는 환경에서, When 신호 대 잡음비가 기준 이하이면, Then 앱은 신뢰도 낮음 상태를 표시한다.
- Given 무음 구간이 감지되면, When 1초 이상 지속되면, Then 피치 트래킹이 대기 상태로 전환된다.

#### 3.2.2 조성 판별 및 화음 자동 생성

**사용자 스토리**: As a 음악 이론에 익숙하지 않은 사용자, I want to 내가 부른 멜로디에 대해 자동으로 조성을 판별하고 어울리는 화음을 추천받고 싶다, so that 이론을 몰라도 화음을 바로 알 수 있다.

**수용 조건**:
- Given 최소 기준 음 개수 이상의 멜로디가 녹음된 상태에서, When 녹음이 종료되면, Then 앱은 판별된 조성과 신뢰도를 표시한다.
- Given 조성이 판별되면, When 사용자가 특정 음을 선택하면, Then 해당 음의 3도/5도 화음 후보가 표시된다.
- Given 멜로디가 너무 짧거나 조성이 모호하면, When 판별이 실패하면, Then 앱은 재녹음을 안내한다.

#### 3.2.3 화음 발성 훈련 및 채점

**사용자 스토리**: As a 훈련 중인 사용자, I want to 생성된 화음을 목표음 삼아 따라 부르고 정확도를 채점받고 싶다, so that 실제로 화음을 부를 수 있는 능력을 기를 수 있다.

**수용 조건**:
- Given 목표 화음이 제시된 상태에서, When 사용자가 노래하면, Then 목표음과의 편차가 실시간 그래프로 표시된다.
- Given 사용자의 음정이 목표음에서 기준치 이상 벗어나면, When 실시간 판정이 이루어지면, Then 시각적으로 벗어남이 표시된다.
- Given 세션이 종료되면, When 결과 화면으로 이동하면, Then 정확도 요약과 자주 벗어난 화음 유형이 표시된다.

**엣지 케이스 (추가 논의 필요)**:
- 사용자가 옥타브를 다르게 불렀을 때(옥타브 오차) 정답으로 인정할지 여부
- 비브라토가 큰 발성을 정확도 판정에서 어떻게 다룰지

## 7. Q&A (예상 질문 및 답변)

**Q. 짧은 허밍만으로 조성을 정확히 판별할 수 있나?**
A. 최소 음 개수 기준을 두고, 신뢰도가 낮으면 재녹음을 유도하는 방식으로 리스크를 낮춘다. 정확한 임계값은 프로토타입 검증 후 확정 [추가 논의 필요].

**Q. 소스 분리 없이 v1이 실용적인가?**
A. v1은 사용자가 직접 부르는 멜로디만 다루기 때문에 소스 분리가 필요 없다. 기존 곡을 넣는 케이스만 v2로 미뤄졌다.

**Q. 경쟁 앱과 확실히 차별화되는가?**
A. 조사한 범위에서 "화음 자동 도출 + 발성 채점"을 함께 제공하는 앱은 없었다. 다만 시장 조사가 완전하지 않을 수 있어 출시 전 재확인이 필요하다.

| 화음 생성 로직 | 자체 구현 (diatonic 3도/5도 매핑) | 규칙 기반, 서버 불필요 |
| 데이터 저장 | SwiftData | 세션 기록, 로컬 우선 |
| 곡 인식 (v2) | ShazamKit | 무료, 화음 정보는 제공하지 않음에 유의 |
| Watch 연동 (v2) | WatchConnectivity | 진동 피드백 |
| 기존 곡 화음 추출 (v2, 스트레치) | Essentia(온디바이스 임베드 우선) 또는 Klangio API(유료, 폴백) | v1에는 포함하지 않음 |
| 단음 악보 렌더링 (v2, 선택) | 자체 SwiftUI 렌더러 우선, swift-sheet-music은 MusicXML 내보내기 필요해질 때 폴백 검토 | 단선율이라 엔그레이빙 복잡도 낮음 |

## 부록 B. 기술적 리스크 및 보완 방안

| 리스크 | 보완 방안 |
|---|---|
| YIN 알고리즘의 실시간 정확도(레이턴시, 잡음 환경) | pYIN(Probabilistic YIN)으로 확장 — 프레임마다 여러 피치 후보와 확률을 내고 HMM으로 스무딩, 옥타브 오차 강건성도 개선(0.5~1.7% 수준). 잡음 대응은 에너지 임계값 + zero-crossing rate 기반 VAD를 앞단에 배치 |
| 조성 판별이 짧고 불완전한 멜로디에서 정확도 저하 | 원조 Krumhansl-Schmuckler 대신 Temperley(1999) 개정 key profile 채택, 음 개수가 아닌 음 길이로 가중치를 준 pitch-class profile 사용, 신뢰도 수치를 노출해 애매하면 사용자 확인 단계로 폴백 |
| 다성 분리(Chromagram)는 v1 범위 밖, v2에서 정확도 한계 우려 | 자체 Chromagram 구현을 우선 목표로 하되, Spotify의 오픈소스 Basic Pitch(다성 지원, CoreML 변환 기본 제공, Apache 2.0)를 벤치마크 또는 v2 폴백으로 검토 |
